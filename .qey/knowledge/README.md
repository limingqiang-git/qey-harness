# knowledge/ — 团队共识(可审计、可交接)

> 团队对齐的共识**必须落仓库**(git 跟踪),不能存在某人脑子里或个人 memory 里。
> 这是 qey-harness 的长记忆载体——项目演进沉淀的、跨会话稳定的知识。

## 内容

| 目录/文件 | 职责 | 谁写 | 何时写 |
|-----------|------|------|--------|
| `项目级记忆.md` | 架构/技术栈/约定/高风险区总览 | `/qey:scan` 初始填充 + 人工维护 | 接入时 + 架构变化时 |
| `踩坑记录/<域>.md` | 可复用的坑(防重复踩) | bug 排查当场写(第 6 步) | 踩坑时 |
| `业务演进/<流程>.md` | ADR——为什么 A→B→C(难逆/反直觉/真实取舍) | 设计决策落定当场写 | 决策时 |

## 与其他目录的边界

| 目录 | 管什么 | 区别 |
|------|--------|------|
| `knowledge/`(这里) | **沉淀的结论**——经验、踩坑、决策 | 提炼后的、稳定的 |
| `journal/` | **时序流水**——发生了什么 | append-only,不提炼 |
| `domain/` | **代码现状导航**——结构/入口/术语 | 代码地图,不是经验 |
| `specs/` | **业务契约真相**——该做什么 | 行为规格,不是经验 |

## 维护原则

- **更新优先于追加**:过期的知识比没知识更危险
- **freshness 标记**:每条带 `last_verified`,过期可见而非静默误导
- **事件驱动**:踩坑/决策在事情发生的 loop 步骤**当场写**,不拖到收尾
