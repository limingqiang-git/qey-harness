# domain/ — 代码地图(怎么实现的)

> 项目代码的**结构化知识**:目录映射、业务术语、流程、状态机、数据字典。
> **定位**:代码"**怎么实现**"的地图(结构/入口/符号)。区别:`specs/`=行为真相"做什么"、`memory/`=踩坑/决策"为什么"。

## ⭐ 核心原则:domain/ 给方向,代码给真相,对不上就修 domain/

domain/ 是 **hint**,代码是 **truth**。找代码/看链路时走这三步:

1. **hint(给方向)**:先查 domain/(`业务术语.md`/`业务流程.md`/`业务领域/`)——它是「中文功能 ↔ 英文符号」桥,拿候选符号 + 入口(高效;codegraph 只索引英文,直接搜中文必失败)。
2. **验证(代码是 truth)**:用符号 → codegraph/grep 验证**符号还在 + 链路还对**。domain/ 可能 stale/脏,**别盲信**。
3. **自愈(对不上就修)**:不一致 → **以代码为准 + 回写修正 domain/**。

> 这三步也是 CLAUDE.md 铁律。**验的力度由置信度调**(observed 信、inferred 重点验);`/qey-distill` 周期性查旧。
> **为什么必须"先 domain/ 再验证",不能直接 codegraph**:直接全局搜 = 浪费已沉淀 + 中文搜不到;而"用→验→修"是 **domain/ 保鲜的唯一机制**——不读不修,它就静默腐烂(过期知识比没知识更危险)。

## 文件(qey-init 扫描生成,标置信度)

| 文件 | 回答 |
|------|------|
| `domain-map.md` | 代码结构 / 目录权威映射 |
| `业务术语.md` | 术语→代码归属(**中文↔符号桥**,glossary) |
| `业务流程.md` | 业务流程地图(每域一行:干啥+入口符号+表) |
| `状态流程.md` | 状态机(状态值 + 流转 mermaid) |
| `数据字典.md`(deep) | 核心表 / 关键字段 |
| `业务领域/<域>/<子主题>.md`(opt-in) | per-domain 子主题深潜(流程图/状态/数据/陷阱);**三级粒度**:`<域>.md`=索引,`<域>/<子主题>.md`=独立子主题(升级信号见 `业务领域/_template.md`) |

## 与其他目录分工(每个只回答一个问题)

| 目录 | 回答 |
|------|------|
| `domain/` | 代码**怎么实现**(结构/入口/符号) |
| `specs/` | **当前行为真相**(做什么;代码应一致,不一致以此为准) |
| `knowledge/业务演进/` | **为什么**这么设计(ADR) |
| `knowledge/踩坑记录/` | 踩过什么坑 |
| `changes/` | 正在发生什么变化(delta) |
| `rules/` | 必须**怎么写** |
