# 错误/异常处理规范(不吞、不泄、有链路)

> AI 写代码最常翻车:吞异常、catch 太宽、错误直接抛给用户。本文件约束通用底线。

## 原则

1. **不吞异常**——`catch` 里必须有处理(记日志 / 转换 / 降级),禁止空 catch 或只注释。
2. **catch 精准**——catch 具体异常类型,不 catch `Throwable/Exception` 一把梭(除非最外层兜底)。
3. **异常→日志→响应 标准链路**:业务异常 → 记 warn → 对外统一错误响应;系统异常 → 记 error(带堆栈) → 对外通用错误。
4. **对外不泄露内部**——错误响应只含错误码 + 用户可读信息,**不含堆栈/SQL/内部路径/敏感字段**。
5. **异常带上下文**——抛/记异常时带业务上下文(订单号、入参关键值),不只是 message。

## 错误码

- 统一错误码体系(如 `BIZ_001` / `SYS_001`),业务错误与系统错误分段。
- 错误码稳定(不随意改),是对外契约。

## ❌ AI 味(禁止)

| 反例 | 问题 |
|------|------|
| `catch (Exception e) {}` | 吞异常,出问题查无此 bug |
| `catch (Throwable)` 一把梭 | 太宽,连 OOM/中断都吃 |
| 错误直接 `echo e.getMessage()` 给用户 | 泄露内部,体验差 |
| 每层 catch 后重新 `new Exception(e.getMessage())` | 丢原始堆栈 |
| 异常不带业务上下文 | "查询失败"——查什么?哪个单? |

## ✅ 专业

- 最外层(控制器/入口)统一兜底:记 error + 返回标准化错误响应。
- 业务层抛**业务异常**(带错误码 + 业务上下文),不抛裸 RuntimeException。
- 可恢复的降级:catch 后走 fallback 并记 warn,不中断主流程。

## 真实正反对照(来自 westmonth 代码扫描)

### 1. catch 后把异常 message 回吐给接口

❌ 反例:
```php
try { $this->service->update($request->all()); }
catch (\Exception $e) { return response_error($e->getMessage()); }   // 泄露 SQL
```
✅ 正例:
```php
try { $this->service->update($request->all()); }
catch (BusinessException $e) { return response_fail($e->getMessage(), [], $e->getCode()); }
catch (\Throwable $e) { report($e); return response_fail('系统繁忙', [], 500); }
```
**为什么**: `return $e->getMessage()` 泄露 SQL/表名(安全)、无日志(可观测)、未区分业务/系统异常。系统异常 report()+通用文案,业务异常走业务异常类。
**来源**: app/Http/Controllers/Api/BigBagController.php:60、beike/Payments/Services/FyPayService.php:339

### 2. 空 catch{} 静默吞异常

❌ 反例:
```php
try { $payService->close($outTradeNo); } catch (\Exception $e) {}   // 关单失败无声吞
```
✅ 正例:
```php
try { $payService->close($outTradeNo); }
catch (\Throwable $e) { report(new \RuntimeException("关单失败 {$outTradeNo}", 0, $e)); throw $e; }
```
**为什么**: 空 catch 失声,变量保持旧值在错误数据上判定,关键副作用(关单/账期)静默失败运维难发现。
**来源**: beike/Services/Order/OrderMiscService.php:141

### 3. catch 后断链重抛裸 Exception

❌ 反例:
```php
catch (\Throwable $th) { throw new \Exception($th->getMessage()); }   // 丢类型/堆栈/previous
```
✅ 正例:
```php
catch (\Throwable $e) { throw new SignatureVerifyException('签名失败', 0, $e); }   // $e 作 previous
```
**为什么**: 只搬 message 丢原类型/堆栈,排障无法定位;裸 `\Exception` 违反"用业务异常类"。重抛必须把原 `$e` 作第三个参数。
**来源**: app/Http/Middleware/VerifySignUniPayMiddleware.php:81

### 4. Job/Console 用 echo 替代日志

❌ 反例:
```php
catch (\Exception $e) { echo "关闭失败，{$e->getMessage()}"; }   // 不走 Log,Job 报成功
```
✅ 正例:
```php
catch (\Throwable $e) { Log::error('关闭支付失败', ['outTradeNo' => $this->outTradeNo, 'exception' => $e]); throw $e; }
```
**为什么**: echo 不进日志系统,Job 看似成功实际失败,不触发重试。Job 失败应抛出让框架处理。
**来源**: app/Jobs/ClosePayment.php:61
