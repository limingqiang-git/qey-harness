# 外部调用规范(超时、重试、幂等、降级)

> 外部依赖(HTTP/RPC/队列/第三方)是最脆的环节:网络抖动、对端挂了、重复推送。AI 常裸调——无超时无重试。

## 必备四件套

每次外部调用都要有:

1. **超时**——连接超时 + 读超时(明确设值,别用默认无限)。HTTP 建议 connect 1-3s / read 3-10s。
2. **重试**——可重试错误(网络超时/5xx)用指数退避重试 N 次;不可重试(4xx/业务失败)不重试。
3. **幂等**——重复调用不产生重复副作用(唯一键/幂等 token;队列消费必幂等)。
4. **结果校验**——不盲信返回;校验状态码 + 关键字段;异常返回走错误处理。

## 降级与熔断

- 外部不可用时**降级**(返回缓存/默认值/友好提示),不让主流程跟着挂。
- 高频依赖加**熔断**(连续失败到阈值就短路一段时间),防雪崩。

## ❌ AI 味(禁止)

| 反例 | 问题 |
|------|------|
| `httpClient.get(url)` 无超时 | 对端卡死 → 线程耗尽 |
| 失败不重试 / 无脑重试 100 次 | 偶发失败 / 或打爆对端 |
| 推送无幂等键,重复推 | 重复下单/重复扣款 |
| 不校验返回直接用 | 对端返回 null/异常结构 → NPE |
| 外部挂了主流程直接 500 | 应降级 |

## ✅ 专业

- 封装统一 client:内置超时/重试/日志/指标。
- 调用前后打日志(目标 + 耗时 + 结果),error 带上下文。
- 队列消费**必幂等**(消息会重投)。
- 第三方回调**必验签 + 幂等**(防伪造 + 防重复处理)。

## 真实正反对照(来自 westmonth 代码扫描)

### 1. Http/Guzzle 链式调用无 timeout 无异常无校验

❌ 反例:
```php
$data = Http::get($url)->json();   // 无 timeout/无 try/不校验
$promise = Http::post($url, $order);   // 支付无幂等键
```
✅ 正例:
```php
try {
    $resp = Http::timeout(10)->retry(2, 200)->get($url);
    if (! $resp->successful()) throw new ExternalApiException('HTTP '.$resp->status());
    $data = $resp->json();
    if (! isset($data['conversion_rates'])) throw new ExternalApiException('结构异常');
} catch (\Throwable $e) { report($e); return Cache::get('fallback_rates', []); }
Http::timeout(10)->withHeaders(['Idempotency-Key' => $key])->post($url, $order);
```
**为什么**: 链式 `->json()` 三缺陷——无 timeout(挂起)、无 try(支付抛 500)、无校验(body 错当成功);支付缺幂等键致重复扣款。
**来源**: beike/Services/CurrencyService.php:228、Payments/Services/UniPayService.php:298

### 2. 支付/资金类关 SSL 校验

❌ 反例:
```php
curl_setopt($curl, CURLOPT_SSL_VERIFYPEER, FALSE);
curl_setopt($curl, CURLOPT_SSL_VERIFYHOST, FALSE);
```
✅ 正例:
```php
curl_setopt($curl, CURLOPT_SSL_VERIFYPEER, true);
curl_setopt($curl, CURLOPT_SSL_VERIFYHOST, 2);
curl_setopt($curl, CURLOPT_CAINFO, '/etc/ssl/certs/ca-certificates.crt');
// 或用 Guzzle(verify 默认 true)
```
**为什么**: 支付关 SSL 放弃防中间人,数据可被劫持/篡改。保持校验 + CA,或用 Guzzle。
**来源**: beike/Libraries/LianlianPay/LianlianClient.php:50

### 3. curl 秒/毫秒 timeout 互相覆盖

❌ 反例:
```php
curl_setopt($curl, CURLOPT_TIMEOUT, 10);
curl_setopt($curl, CURLOPT_TIMEOUT_MS, $releaseTimeout);   // 毫秒覆盖秒,实际 60s
```
✅ 正例:
```php
curl_setopt($curl, CURLOPT_TIMEOUT_MS, 10000);   // 只用一种
if ($data === false) throw match (curl_errno($curl)) {
    CURLE_OPERATION_TIMEDOUT => new ExternalApiTimeoutException('超时'),
    default => new ExternalApiException('curl: '.curl_error($curl)),
};
```
**为什么**: `TIMEOUT_MS` 覆盖 `TIMEOUT`,同时设实际是后者(60s)非 10s;且失败 `return false` 无法区分错误类型。
**来源**: app/Console/Commands/SwooleServer.php:383

### 4. 远程 file_get_contents 无超时无 false 判断

❌ 反例:
```php
$imageContent = file_get_contents($url);   // 无 timeout,失败返 false 喂下游
```
✅ 正例:
```php
$ctx = stream_context_create(['http' => ['timeout' => 10]]);
$imageContent = @file_get_contents($url, false, $ctx);
if ($imageContent === false) throw new ExternalApiException("获取失败: {$url}");
// 更推荐 Guzzle 统一超时/重试/异常
```
**为什么**: 远程 `file_get_contents` 无 timeout(默认 60s),失败 false 喂下游触发警告。用 stream_context 或 Guzzle。
**来源**: beike/Services/ImageSearch/ImageSearchService.php:134

## 一句话自检

> 这个外部调用:对端慢 10s 会拖垮我吗?重投/重复回调会重复扣款吗?都"会" → 补超时 + 幂等。
