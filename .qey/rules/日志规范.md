# 日志规范(有上下文、不刷屏、不泄密)

> 日志是排查的命脉,也是 AI 最容易乱来:到处 log、打敏感信息、缺上下文。

## 级别(严格)

| 级别 | 用途 | 误用 |
|------|------|------|
| `error` | 影响功能的真实故障(需人介入) | ❌ 业务正常分支用 error |
| `warn` | 可恢复的异常/降级/越界(值得关注) | ❌ 当 info 用 |
| `info` | 关键业务节点(下单/支付/状态流转) | ❌ 循环里打 info |
| `debug` | 排查细节,生产关 | ❌ 生产依赖 debug 看问题 |

## 必带上下文

- 每条日志带 **traceId / 请求Id**(串联一次调用链)。
- 业务日志带**关键业务标识**(订单号/用户id/操作),不只是 message。
- 打入参时只打**关键值**,不打整个大对象/敏感字段。

## ❌ AI 味(禁止)

| 反例 | 问题 |
|------|------|
| 循环里 `log.info(...)` | 刷屏,生产日志爆炸 |
| `log.error("失败", e)` 不带业务上下文 | 排查时不知道哪个单失败 |
| 打 `password` / `token` / 整个 user 对象 | 泄露 |
| `System.out.println` 调试残留 | 不是日志,生产污染 |
| 同一件事打 3 遍(info+debug+print) | 冗余 |

## ✅ 专业

- 结构化日志(key=value 或 JSON),便于检索。
- 敏感字段脱敏后再打(`138****1234`)。
- 异常日志打 `error` 且带堆栈 + 业务上下文。
- 入口打一条 info(请求摘要),出口打一条(结果/耗时)。

## 真实正反对照(来自 westmonth 代码扫描)

### 1. 敏感字段明文落日志

❌ 反例:
```php
Log::info("access_token 获取", ['access_token' => $token]);
Log::info(':aliSmsSendMsg:Phone'.$phone.':'.json_encode($result));
```
✅ 正例:
```php
Log::info('access_token 已获取', ['length' => strlen($token), 'fingerprint' => hash('sha256', $token)]);
Log::info('aliSmsSendMsg', ['phone' => mask_phone($phone), 'result_code' => $result['code'] ?? null]);
```
**为什么**: token 等价身份凭证,明文落日志可被冒用;手机号全量是敏感信息。token 打指纹,手机号走 `mask_phone()` 工具函数。
**来源**: beike/Payments/Services/UserTokenService.php:27、Mobile/Service/WechatQrCodeService.php:34

### 2. dd/var_dump 调试残留进生产

❌ 反例:
```php
catch (\Exception $e) { dd($e); return response_error('...'); }   // return 永不可达
catch (OssException $e) { var_dump($e->__toString()); Log::error(...); }
```
✅ 正例:
```php
catch (\Throwable $e) { report($e); return response_fail('系统繁忙'); }
// CI 加 sniff 禁止 dd/var_dump/dump/print_r 进 src
```
**为什么**: `dd()` 终止进程,`var_dump` 污染响应,异常吞没不进日志。CI 阶段禁止这些函数进 src。
**来源**: beike/Order/Services/OrderLabelsService.php:643、Common/Services/OssService.php:165

### 3. 循环内逐条打日志 + 正常分支误用 error

❌ 反例:
```php
foreach ($orderTracks as $track) { Log::info($track->order_number.'订阅:'.$num); }   // 千条千行
if (empty($uids[...])) { Log::error('无法获取uid'); continue; }   // 正常跳过用 error
```
✅ 正例:
```php
foreach (...) { try { /*...*/; $success++; } catch (\Throwable $e) { $failed[] = /*...*/; } }
Log::info('物流订阅完成', ['total' => count(...), 'success' => $success, 'failed' => $failed]);
Log::debug('跳过无 uid', ['customer_id' => /*...*/]);   // 正常分支用 debug
```
**为什么**: 循环逐条打日志爆炸;正常分支误用 error 污染告警,真错误被淹没。循环汇总成一条,正常分支用 debug/info。
**来源**: app/Console/Commands/Logistics/LogisticsSubscription.php:72、RebateService.php:665

### 4. 脱敏不彻底(context 脱了 message 拼原文)

❌ 反例:
```php
$pregPhone = preg_replace('/^(\d{3})(\d{4})(\d{4})$/', '$1****$3', $phone);
Log::info('...手机号'.$phone.'发送:'.json_encode(['phone' => $pregPhone]));   // message 又拼原 $phone
```
✅ 正例:
```php
$masked = mask_phone($phone);
Log::info('短信通知', ['phone' => $masked, 'content' => $params]);   // 全程只用脱敏值
```
**为什么**: context 脱敏却 message 拼原文 = 形同虚设。原始变量打日志前必经 `mask_phone()`,message 和 context 全程只用脱敏值。
**来源**: beike/Services/Customer/CustomerCancellationService.php:386

## 一句话自检

> 这条日志在生产被检索时,能定位到"哪个请求、哪条业务数据、为什么"吗?不能 → 补上下文。
