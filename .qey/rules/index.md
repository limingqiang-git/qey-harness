# Rules Index(规范路由)

> 改代码前,按场景读对应规范(**不全读,精准加载**)。
> 本文件是入口,路由到具体规范文件。
>
> **结构**(1.6 渐进分层):
> - 根目录:通用规范(git/注释/安全/错误/日志/外部)+ 项目特定(各层/陷阱/定位)
> - `thinking-guides/`:思维指南(改代码前触发"该不该想想")
> - `shared/`(规划中):通用规范归类(渐进迁移,当前先在根)
> - `backend/`(规划中):后端特定(项目填充)
> - `database/`(规划中):数据库特定(项目填充)

---

## 改代码前:按场景路由

| 你要干的事 | 先读 | 为什么 |
|-----------|------|--------|
| **改任何代码**(先想) | `thinking-guides/index.md` | 30 秒防"没想到"的 bug(跨层/复用/状态机/边界) |
| 改后端代码(DDD/Service/Domain) | `各层规范.md` + `backend/index.md`(若已建) | 分层约定 |
| 改数据库(迁移/索引/表) | `各层规范.md` 数据层段 + `database/index.md`(若已建) | 持久化约定 |
| 提交代码 | `git提交规范.md` | commit 规范 + MR 标题 |
| 写注释 | `代码注释规范.md` | 克制、无 AI 味,只注 why |
| 处理异常/错误 | `错误处理规范.md` | 不吞异常/错误码/不泄露堆栈 |
| 打日志 | `日志规范.md` | 级别/traceId+上下文/脱敏 |
| 调外部服务(RPC/队列/HTTP) | `外部调用规范.md` | 超时/重试/幂等/降级 |
| 安全相关(SQL/密钥/脱敏/越权) | `安全规范.md` | 防御底线 |
| 找代码/定位功能 | `代码定位决策树.md` | LSP/codegraph/grep 任务匹配 |
| 改代码前查已知陷阱 | `历史遗留陷阱.md`(项目特定) | 防命名踩坑 |

## 所有改动都适用

- `thinking-guides/`(改代码前必扫触发清单)
- `历史遗留陷阱.md`(项目特定,改代码前扫已知坑)

---

## 规范 vs 思维指南(关键区别)

| 类型 | 位置 | 目的 | 内容风格 |
|------|------|------|---------|
| **规范**(本目录根 + shared/backend/) | `rules/*.md` | 告诉"**怎么写**" | 签名、契约、正反例 |
| **思维指南** | `rules/thinking-guides/*.md` | 帮"**该想什么**" | 清单、问题、指向规范 |

**决策规则**:
- "这是**怎么写**代码" → 放规范(本目录)
- "这是**写之前该考虑什么**" → 放思维指南(thinking-guides/)

## 渐进分层(规划中)

当前规范在根目录(扁平)。规划渐进迁移到分层结构:

```
rules/                (当前:扁平)
  index.md            ← 本文件(路由)
  git提交规范.md       ← 通用
  代码注释规范.md      ← 通用
  安全规范.md          ← 通用
  错误处理规范.md      ← 通用
  日志规范.md          ← 通用
  外部调用规范.md      ← 通用
  各层规范.md          ← 分层骨架(项目填充)
  代码定位决策树.md    ← 工具选型
  历史遗留陷阱.md      ← 项目特定
  thinking-guides/    ← 思维指南(1.6 已建)

rules/                (规划:渐进分层,不破坏现有)
  index.md            ← 路由(本文件)
  shared/             ← 通用规范(渐进迁移自根)
    git.md
    comments.md
    ...
  backend/            ← 后端特定(项目填充)
    index.md          ← Pre-Dev Checklist
    ddd-conventions.md
  database/           ← 数据库特定(项目填充)
    index.md
  thinking-guides/    ← 思维指南
  历史遗留陷阱.md      ← 项目特定(保持根)
  代码定位决策树.md    ← 工具选型(保持根)
```

> **渐进原则**:不强制移动现有文件(避免破坏项目填充)。新项目可选分层;老项目保持扁平,index.md 都能路由。
