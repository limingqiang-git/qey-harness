# 代码注释规范(克制、专业、无 AI 味)

> AI 写代码常犯的毛病:堆废话注释、把方案说明塞进代码、注释比代码长。
> 本文件约束:注释**只注 why,不注 what**;能不注就不注。

## 核心原则

1. **注释解释"为什么",不解释"是什么"**——代码和命名已说明 what,注释只补 why / 坑 / 约束 / 非显然决策。
2. **能不注就不注**——命名清晰、逻辑自明的代码**不注释**。注释是例外,不是常态。
3. **不写方案说明**——方案、设计、背景属于 spec / 文档,**不重复进代码注释**。
4. **注释跟着代码改**——代码变了注释同步改;过时注释比没注释糟。

## ❌ AI 味(禁止)

| 反例 | 问题 |
|------|------|
| `// 用户管理方案:本模块采用 XXX 模式...` | 把方案/设计塞进注释(方案在 spec) |
| `// @这是 xxx 的实现方案` | 元说明/归属,不是给读代码人的 |
| `function getUser()` 后 `// 获取用户` | 显而易见,命名已自明 |
| `i++; // 计数加一` | 废话注释 |
| `// ============ 用户模块 ============` | 装饰性分隔 |
| `// 结束` / `// 返回结果` | 尾注废话 |
| `// 这里采用了单例模式` | 把实现决策当注释炫耀 |
| 注释比代码长 | 喧宾夺主 |

## ✅ 专业(鼓励)

| 场景 | 写法 |
|------|------|
| 非显然的 why | `// 乐观锁:该场景冲突率<1%,换吞吐` |
| 坑/陷阱 | `// 第三方回调可能重复,下面做幂等` |
| 约束/边界 | `// 金额单位是分,勿直接转元(精度)` |
| 临时/待办带上下文 | `// TODO: 等 XX 接口就绪后换(task#123)` |
| 复杂逻辑的简短意图 | `// 把扁平列表重建为树`(只一行,仅当代码不能自明时) |
| 公共 API 契约 | 用语言原生 doc 注释;只注非显然项,不逐个 @param 啰嗦 |

## 类/模块 docblock 的度

类级注释写**本类的**:职责(一行) + 本类独有的 why/约束 + 用法(CLI 命令/公共 API) + `@see` 指向方案。

**不写**:整体架构总结(如"组成三重保障")、别的类怎么配合、方案全文——这些在方案文档里,类注释用 `@see` 指过去。

| ✅ 该写 | ❌ 别写 |
|--------|--------|
| 本类做什么(一行) | 整体架构定位/总结("三重保障") |
| 本类独有的非显然决策(如 `requeue=false` 的兜底) | 别的类的职责 |
| CLI 命令用法 `php bin/...` | 方案背景/演进史 |
| `@see 方案.md` | 把方案内容搬进注释 |

> **同一机制跨多个类时**(如 Listener/Command/Consumer 都服务"通知 westmonth"):每个类只写自己的职责 + 本类独有的 why;**整体方案集中一份文档**,各类 `@see` 它——不要把方案片段复制到每个类注释。
>
> 自检:这条注释说的是"**本类**干啥/为啥",还是"**整体**怎么搭"?后者删掉,挪去 `@see` 的文档。

## 语言

- **跟随项目主语言**:PHP/Go/Java/TS 等英文项目用英文注释;国内业务密集、团队约定中文的用中文。
- **一个文件内统一**,不中英混注。
- **术语用英文原词**,不强行翻译(transaction / idempotent / retry)。

## 真实正反对照(来自 westmonth 代码扫描)

> 真实代码提炼,带 file:line。写注释时对照。

### 1. docblock 即方法名的中文翻译

❌ 反例:
```php
/** 获取所有店铺 */
public function getShops(): array
/** 获取post数据 */
private function getPostData(): array
```
✅ 正例:
```php
public function getShops(): array   // 命名自明,删 docblock
/** 仅返回启用中的店铺,按 sort 倒序。空结果返回 [] 而非 null。 */
public function getShops(): array   // 只在方法名无法表达约束时写
```
**为什么**: getXxx/setXxx 方法名自注释,docblock 只翻译方法名 = 零信息增量。
**来源**: beike/Services/JuShuiTanServices.php:351、AlarmService.php:15、LoadProductListService.php:634

### 2. docblock 堆功能清单 + 保障口号

❌ 反例:
```php
/**
 * 更新字段值的定时脚本
 * 功能特性:
 * - 支持dry-run模式
 * - 完整的日志记录
 * - 错误处理和数据完整性保障
 * - 事务保证数据一致性
 */
class UpdateFieldCommand

/** 1.分布式锁 2.查询数据 3.调用服务 4.处理异常 */
public function handle()
```
✅ 正例:
```php
/** 每日凌晨把已发货订单的 shipped_at 同步到冗余表。dry-run 仅输出行数不写库。 */
class UpdateFieldCommand
// 方法体几步时别用编号列表复述;docblock 只留"为什么":
public function handle(): int { $lock = Cache::lock('update-field', 60); /*...*/ }
```
**为什么**: "功能特性"+"数据完整性保障""事务保证一致性"是 AI 营销腔(罗列卖点不解释意图);1.2.3.4 复述代码,注释比代码长。
**来源**: app/Console/Commands/UpdateOrdersShippedAt.php:13、Order/OrderLogistics.php:67

### 3. 装饰分隔线包裹废话小节标题

❌ 反例:
```php
// ----------------------------------------------------------------
// 一、确定统计日期范围
// ----------------------------------------------------------------
$startDate = $this->option('start-date');
```
✅ 正例:
```php
$startDate = $this->option('start-date');   // 标题复述下一行就删
// 方法真长需分段,用有信息量的注释:
$records = Model::where('date', '>=', $startDate)->where('period_status', 'closed')->get();  // 仅统计已关账期,避免重复入账
```
**为什么**: 装饰线包废话标题既造噪声又把显而易见的代码总结成废话;分段靠提取私有方法或有信息量注释。
**来源**: app/Console/Commands/DailyCustomerStatCommand.php:75

### 4. 同一机制注释跨类复制粘贴

❌ 反例:
```php
// 9 个同构 ApiServices 类逐字复制同一句:
$code = $order['freight_operator_code']; //快递编码兜底逻辑
```
✅ 正例:
```php
trait FreightCodeResolver {
    /** 运营商编码缺失回退默认渠道,避免空编码被拒。 */
    protected function resolveFreightCode(array $order): string {
        return $order['freight_operator_code'] ?? config('freight.default_code');
    }
}
```
**为什么**: 同句注释 9 个类复制违反 DRY,改一处忘改其余;抽公共方法注释只写一次。
**来源**: beike/Services/WinitApiServices.php:118 及 8 个同类

## 一句话自检

> 删掉这条注释,代码还能读懂吗?能 → 删。不能、且原因是"为什么这么写" → 留。
